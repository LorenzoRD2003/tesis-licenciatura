\subsection{Definición e intuición}

Los Merkle Trees son estructuras de datos basadas en árboles binarios y funciones de hash criptográficas que se utilizan extensivamente como parte de protocolos criptográficos en el \ROM. Por ejemplo, son utilizadas en la red de \Bitcoin desde sus inicios \cite{nakamoto2009bitcoin}. Fueron introducidas por Merkle en \cite{Merkle1988}.

\begin{definition}[Merkle Tree]
	Sea $L = \{\ell_1, \ldots, \ell_n\} \subset \Strings{*}$ una secuencia ordenada de datos, y sea $\Hash: \Strings{*} \to \Strings{n}$ una función de hash criptográfica. Un Merkle Tree es un árbol binario $\MerkleTree{T}_{L,\Hash}$ (notado $\MerkleTree{T}$ por comodidad) completo cuyas hojas corresponden a los elementos de $L$, definido recursivamente de la siguiente manera:
	\begin{enumerate}
		\item En el nivel inferior, están las hojas del árbol, que son los hashes de los datos ordenados: $h_i = \Hash(\ell_i)$, para $1 \leq i \leq n$.
		\item Cada nodo interno $N$ con hijos $N_i$ (nodo hijo izquierdo) y $N_d$ (nodo hijo derecho) se define como $N = \Hash(N_i \concat N_d)$, donde $\concat$ denota la operación de concatenación en $\Strings{*}$.
		\item La raíz del árbol se nota $\MerkleRoot{\MerkleTree{T}}$. Es el nodo que sintetiza criptográficamente toda la información de $L$.
	\end{enumerate}
	 Si $n$ no es una potencia de $2$, se completa la lista de hojas mediante una función de \textit{padding} determinística.
\end{definition}

La propiedad clave de un Merkle Tree $\MerkleRoot{\MerkleTree{T}}$ es que cualquier modificación en un dato $\ell_i$ provoca un cambio en su hoja asociada $\Hash(\ell_i)$, y se propaga hasta $\MerkleRoot{\MerkleTree{T}}$ de una forma impredecible. Esto permite verificar la integridad de un elemento específico sin necesidad de recorrer o almacenar toda la secuencia de datos. Cualquier modificación en un dato (incluso en un solo bit) permite detectar alteraciones de forma inmediata solamente verificando si cambió el valor de $\MerkleRoot{\MerkleTree{T}}$.

Por supuesto, los elementos de la secuencia de datos puede pertenecer a cualquier conjunto arbitrario $X$ mientras todos sus datos sean finitos, y transformarlos a tiras de bits, replicando lo que hicimos en la sección anterior.

Observar que en las imágenes se indica la secuencia de datos por debajo de $\MerkleTree{T}$, pero se recalca que estos no pertenecen directamente a $\MerkleTree{T}$, sino que el nivel inferior de $\MerkleTree{T}$ está compuesto por los $\Hash(\ell_i)$.

\subsection{Merkle Proofs}

Otra cosa importantísima que nos permite hacer esta estructura son pruebas de pertenencia, también conocidas como Merkle Proofs. Esta es la primera introducción a las pruebas que vamos a tener en el desarrollo de esta tesis. Una Merkle Proof permite demostrar que un elemento pertenece a un Merkle Tree $\MerkleTree{T}$ sin necesidad de revelar todos los elementos de la secuencia de datos asociada, lo que es útil para no tener que almacenar la totalidad de $\MerkleTree{T}$ para verificar un solo dato, sino solamente $\MerkleRoot{\MerkleTree{T}}$. En algún lugar se tiene que guardar $\MerkleTree{T}$, pero hace innecesario replicarlo en más lugares.

\begin{definition}[Merkle Proof]
	Sea $\MerkleTree{T}$ un Merkle Tree con raíz $\MerkleRoot{\MerkleTree{T}}$, construido sobre una secuencia de datos $L = \{\ell_1, \ldots, \ell_n\}$ y usando una función de hash criptográfica $\Hash$. Una Merkle Proof para un dato $\ell = (b_1, \ldots, b_k) \in L$ es una lista ordenada $\MerkleProof = [h_1, \ldots, h_k]$ que representa un camino (Merkle Path) desde la hoja correspondiente a $\ell$ hasta $\MerkleRoot{\MerkleTree{T}}$, donde:
	\begin{itemize}
		\item Cada $h_i \in \Strings{n}$ es el hash del hermano del nodo del nivel $i$ en el Merkle Path desde la hoja correspondiente a $\ell$ hasta $\MerkleRoot{\MerkleTree{T}}$.
		\item Cada $b_i \in \{0,1\}$ es el $i$-ésimo bit de $\ell$, e indica si el hash $h_i$ está a la izquierda ($b_i = 0$) o a la derecha ($b_i = 1$) del nodo en el Merkle Path..
		\item $k = \lceil \log_2 n \rceil$ es la altura de $\MerkleTree{T}$, por lo tanto la cantidad de pasos en el Merkle Path hasta $\MerkleRoot{\MerkleTree{T}}$.
	\end{itemize}
\end{definition}

Intuituivamente, una Merkle Proof es el conjunto de nodos hermanos a lo largo del camino desde una hoja hasta la raíz del Merkle Tree.

En la imagen de una Merkle Proof, se observa que es una prueba de pertenencia de $\ell_3$, y que $\MerkleProof = [h_4, h_{12}]$. Se puede definir una función (y su algoritmo correspondiente) para verificar que una Merkle Proof es correcta. La idea es reconstruir determinísticamente los nodos del Merkle Path del dato en $\MerkleTree{T}$ (en azul en la figura \ref{fig:verify-merkle-proof}) usando $\MerkleProof$ (en rojo en la figura \ref{fig:verify-merkle-proof}) para llegar hasta $\MerkleRoot{\MerkleTree{T}}$, y verificar que es igual al valor esperado. Los bits $b_i$ son esenciales para preservar el orden de concatenación dentro del input de $\Hash$.

La seguridad criptográfica de un Merkle Tree se reduce a la resistencia a colisiones de su función de hash. En efecto, una colisión permitiría construir dos subárboles distintos con la misma raíz, comprometiendo la solidez de las pruebas de pertenencia (ver \cite{hac,katz}).

\begin{definition}[Función de verificación de Merkle Proof]
	Sea $\MerkleTree{T}$ un Merkle Tree con raíz $\MerkleRoot{\MerkleTree{T}}$, construido usando una función de hash criptográfica $\Hash$, y sea $\MerkleProof$ una Merkle Proof para un dato $l \in L$. Definimos la función de verificación de $\MerkleProof$ como:
	$$\Verify(\ell, \MerkleProof, \MerkleRoot{\MerkleTree{T}}) = \llbracket x_k = \MerkleRoot{\MerkleTree{T}} \rrbracket,$$
	donde
	$$x_0 := \Hash(\ell), \qquad x_i := \begin{cases}
		\Hash(h_i \concat x_{i-1}) & \text{si } b_i = 0, \\
		\Hash(x_{i-1} \concat h_i) & \text{si } b_i = 1,
	\end{cases} \quad 1 \leq i \leq k.$$
\end{definition}

\begin{algorithm}[h]
	\caption{Verificación de una Merkle Proof}
	\label{alg:verify-merkle-proof}
	\begin{algorithmic}[1]
		\Require Dato $\ell \in \Strings{*}$, Merkle Proof $\MerkleProof = [h_1, \ldots, h_k]$, raíz $\MerkleRoot{\MerkleTree{T}} \in \Strings{n}$
		\Ensure \textbf{true} si $\MerkleProof$ prueba que $\ell \in \MerkleTree{T}$, \textbf{false} en caso contrario
		\State $(b_1, \ldots, b_k) \gets \ell$ \Comment{representación binaria de $\ell$}
		\State $x \gets \Hash(\ell)$
		\For{$i = 1$ \textbf{to} $k$}
		\If{$b_i = 0$} \Comment{$h_i$ es hijo izquierdo}
		\State $x \gets \Hash(h_i \concat x)$
		\Else \Comment{$h_i$ es hijo derecho}
		\State $x \gets \Hash(x \concat h_i)$
		\EndIf
		\EndFor
		\State \Return $\llbracket x = \MerkleRoot{\MerkleTree{T}} \rrbracket$
	\end{algorithmic}
\end{algorithm}

Notar que el algoritmo \ref{alg:verify-merkle-proof} tiene una complejidad temporal de $\BigO(k) = \BigO(\log n)$, así como el tamaño de la Merkle Proof. Para árboles con muchos niveles, esto resulta clave. Además, no resulta necesario almacenar todo el vector camino $x$ durante el mismo.

Desde una perspectiva criptográfica, los Merkle Trees pueden interpretarse como esquemas de compromiso vectorial \cite{Catalano2013} con pruebas de tamaño logarítmico. Esta interpretación será particularmente relevante en el desarrollo de sistemas de pruebas del siguiente capítulo.
